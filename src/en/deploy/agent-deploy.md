# Agent side deployment

This article describes how to deploy the Matrix Agent. The Agent is green (portable) software that runs on the computer where test phones are plugged in. Once connected to the server, your team can remotely control real devices and run automated tests from the web UI.

> Release page: [github.com/felixyang007/matrix-agent/releases](https://github.com/felixyang007/matrix-agent/releases) (requires team GitHub access)
> Source repo: [github.com/felixyang007/matrix-agent](https://github.com/felixyang007/matrix-agent)

::: tip notes
- Only one Agent per machine; each Agent Key cannot be reused.
- Multiple devices can connect to the same Agent.
- Keep the Agent version consistent with the Server version.
- A wired network is recommended (screen casting / remote control is bandwidth-heavy).
:::

## Before you start: 4 things to prepare

1. A **Mac or Linux** machine (the one that stays on with test phones attached).
2. **Test phone + USB cable** (Android real device; use a good cable, avoid hubs).
3. **Server address** (e.g. `10.2.3.9:3000`, ask your admin — it is the URL of the test platform).
4. **Agent Key** (generated by an admin in the web UI: Device Center → Agent Center → Add).

> No admin password or database is needed — the Agent works right after unzipping.

## Step 1: Install Java 17

```bash
java -version
```

If it shows `17.x.x` or higher, skip to step 2. Otherwise install OpenJDK 17:

```bash
# macOS
brew install openjdk@17
sudo ln -sfn /opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk /Library/Java/JavaVirtualMachines/openjdk-17.jdk
```

> For Linux, install OpenJDK 17 with your distro's package manager (e.g. `sudo apt install openjdk-17-jdk`).

## Step 2: Download and unzip the Agent package

Check your CPU architecture first:

```bash
uname -m
```

- `arm64` → Apple Silicon (M1/M2/M3/M4)
- `x86_64` → Intel

Download the matching zip from the team release page:

👉 [github.com/felixyang007/matrix-agent/releases](https://github.com/felixyang007/matrix-agent/releases)

- Apple Silicon: `*macosx_arm64.zip`
- Intel: `*macosx_x86_64.zip`
- Linux: `*linux_x86_64.zip`

After unzipping you should see:

```text
sonic-agent-macosx-arm64.jar   config/   plugins/   mini/
```

> This release already bundles: adb 37.0.1, uiautomator2-server 10.6.2, Android 14+ screen-cast patch, scrcpy 1.23-patched, etc. We refer to this directory as the working directory (e.g. `~/matrix-agent`).

## Step 3: Fill in the config

Edit `config/application-sonic-agent.yml` in the working directory:

```yaml
sonic:
  agent:
    # use 127.0.0.1 if only YOU view devices in the browser here (recommended);
    # otherwise use this machine's LAN IP so teammates can view the live screen
    host: 127.0.0.1
    # Agent screen-cast port (usually unchanged)
    port: 7777
    # Key generated when adding an Agent in the web UI
    key: <your Agent Key>
  server:
    # server IP from your admin
    host: 10.2.3.9
    # server port (default 3000)
    port: 3000

# Will be migrated to server config in the future
modules:
  ios:
    wda-bundle-id: com.sonic.WebDriverAgentRunner
    wda-xcode-project-path: ~/matrix-ios-wda/WebDriverAgent.xcodeproj
    simulator:
      enabled: false
      poll-interval-seconds: 10
      fresh-instance-per-task: false
```

::: tip How to fill `host` (most common pitfall)
- **Only you view devices on this machine** → use `127.0.0.1` (strongly recommended: always works even when the IP changes).
- **Teammates also need to view** → use the LAN IP and set a DHCP reservation so the IP stays fixed.
:::

## Step 4: Start the Agent

```bash
cd ~/matrix-agent
nohup java -Dfile.encoding=utf-8 -Dspring.profiles.active=sonic-agent \
  -jar sonic-agent-*.jar > agent.log 2>&1 & disown
```

Wait ~10 seconds and verify (both lines = success):

```bash
grep -E "server auth successful|Enable Android Module" agent.log
```

Then open the platform web UI → Device Center → Agent Center; your agent should be **online**.

## Step 5: Connect your phone

1. On the phone: enable Developer Options, then enable **USB debugging**.
2. Connect the phone and tap **Always allow** on the debugging prompt.
3. Verify:

```bash
~/matrix-agent/plugins/adb devices -l
```

Status `device` means it is recognized (`unauthorized` means the prompt was missed). After ~10 seconds the device becomes **online** in Device Center; click "Remote Control" to operate it.

> Android emulators (Android Studio) are recognized like real devices; see the next section for the iOS simulator.

## Advanced: attach an iOS simulator (Xcode Simulator)

When you don't have an iPhone plugged in, Xcode's simulator can run iOS automation (smoke / fast regression). Requirement: **Apple Silicon Mac + Xcode installed (with at least one iOS simulator runtime)**.

### 1) Boot a simulator

```bash
xcodebuild -version
xcrun simctl list devices
```

Create and boot one if needed:

```bash
xcrun simctl create "Matrix-iOS-1" "com.apple.CoreSimulator.SimDeviceType.iPhone-15-Pro" iOS-18.0
# ↑ outputs a udid
xcrun simctl boot "<the udid above>"
```

### 2) Prepare the WDA (WebDriverAgent) project

```bash
cd ~ && git clone git@github.com:felixyang007/matrix-ios-wda.git
# project path = ~/matrix-ios-wda/WebDriverAgent.xcodeproj
```

> This is a private repo. Use `https://github.com/felixyang007/matrix-ios-wda.git` if SSH is not configured. If you have no access at all, ask an admin for a packed copy and unzip it to `~/`.

### 3) Let the Agent discover the simulator + WDA

Append to the config:

```yaml
modules:
  ios:
    wda-xcode-project-path: ~/matrix-ios-wda/WebDriverAgent.xcodeproj
    simulator:
      enabled: true
      poll-interval-seconds: 10
      fresh-instance-per-task: false
```

### 4) Restart and confirm

```bash
cd ~/matrix-agent
pkill -f "sonic-agent-.*\.jar"; sleep 2
nohup java -Dfile.encoding=utf-8 -Dspring.profiles.active=sonic-agent -jar sonic-agent-*.jar > agent.log 2>&1 & disown
sleep 10 && grep -E "Enable iOS Simulator module|server auth successful" agent.log
```

`Enable iOS Simulator module` means the simulator module is loaded; the simulator appears in Device Center with a "simulator" badge.

> The simulator can only install **simulator builds** (real-device arm64 IPAs won't install); payment / push / biometrics / risk-control cases behave unreliably on the simulator — use a real device.

## FAQ

**Q1: Agent can't reach the server (no `server auth successful`)?**

1. Most common: wrong **Agent Key** — copy it from the web UI exactly.
2. **Server address unreachable**: can the browser open `http://server-address`? If not, ask an admin.
3. **Duplicate process**: only one agent per machine — `pgrep -fl sonic-agent` should show a single Java process.

**Q2: Device page keeps spinning / remote control can't show the screen?**

Most common: the machine IP changed. Compare `ipconfig getifaddr en0` with `agent.host` in the yml; fix it or use `127.0.0.1`, then restart the Agent.

**Q3: Blank screen (page opens but no picture)?**

Android 14+ needs the screen-cast patch. New agent packages already include the fix; for older packages run:

```bash
tools/android14-scrcpy-fix/patch-agent-scrcpy.sh ~/matrix-agent --restart
```

**Q4: Device keeps going online/offline?**

1. Check the cable first (most common): use a good cable, direct port, no hub.
2. Check adb conflicts: another adb with a different version fights with the bundled one — unify versions (the team adb upgrade script targets 37.0.1).

**Q5: macOS says "developer cannot be verified / blocked"?**

System Settings → Privacy & Security → click "Open Anyway" for the blocked item. Do **not** disable Gatekeeper globally.

## Daily maintenance (3 tricks)

**Restart the Agent (solves 80% of issues)**

```bash
cd ~/matrix-agent
pkill -f "sonic-agent-.*\.jar"; sleep 2
nohup java -Dfile.encoding=utf-8 -Dspring.profiles.active=sonic-agent -jar sonic-agent-*.jar > agent.log 2>&1 & disown
sleep 10 && grep "server auth successful" agent.log
```

**Read logs**

```bash
tail -100 ~/matrix-agent/agent.log          # last 100 lines
grep -i error ~/matrix-agent/agent.log      # errors only
```

**Upgrade the Agent**

When an admin sends a new zip: unzip it → overwrite the `jar` and `plugins/` in the working directory (**keep your `config/`**), then restart. Or replace the whole directory and redo step 3.
